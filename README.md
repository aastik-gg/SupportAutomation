# Support Automation

AI-assisted customer support console built with FastAPI, SQLAlchemy, and a React/Vite frontend. Incoming tickets can be synced from Gmail, triaged in the dashboard, edited, and dispatched with Gemini 2.5 Flash suggested replies.

## What this project does
- **Ingests support mail** – Pulls unread Gmail threads (via the Gmail API) and stores them as actionable tickets in SQLite or PostgreSQL (any SQLAlchemy URL works).
- **Drafts AI replies** – Every ticket gets an initial response from Gemini 2.5 Flash so agents start from a useful baseline instead of a blank textarea.
- **Human-in-the-loop edits** – Agents tweak the draft inside the web UI, save intermediate versions, and mark tickets as `edited` or `pending`.
- **Send & archive** – With one click the finalized reply is sent back through Gmail, the ticket is marked `resolved`, and it moves to the Sent column.
- **Session-aware dashboard** – An admin-only SPA tracks authentication via secure HTTP-only cookies, enforcing access control on every API call.

## Feature highlights
- **Full-stack ready** – Backend and frontend are configured to build/deploy together; Vite’s production output is served directly by FastAPI under `/static`.
- **Configurable origins** – CORS + cookie settings adapt to localhost, staging, or hosted URLs using the `FRONTEND_ORIGINS` variable.
- **Service modularity** – Auth, AI, Gmail, and ticket logic live in separate service modules so swapping providers (e.g., different LLM or mail relay) is straightforward.
- **Observability** – Structured logging (token previews, session checks, AI fallbacks) makes diagnosing auth or AI issues easier in production logs.
- **Database flexibility** – Uses SQLite by default but works with any SQLAlchemy-compatible database by changing `DATABASE_URL`.

## Architecture
- **backend/** – FastAPI application with session middleware, ticket APIs, Gmail sync, and Gemini-powered reply generation.
- **support-frontend/** – React SPA served by Vite during development and bundled into `backend/static/` for production.
- **support.db** – SQLite database storing tickets during local development (override `DATABASE_URL` to point at PostgreSQL, Neon, Supabase, Render, etc.).

## Prerequisites
- Python 3.12+
- Node.js 20+
- Google Cloud project with a Gemini API key (`GEMINI_API_KEY`).
- Gmail API credentials (`backend/credentials.json` and `backend/token.json`) if you plan to sync or send email from Gmail.

## Environment variables
Create a `.env` file in the project root (already ignored by Git):

```env
DATABASE_URL=postgresql+psycopg2://USER:PASSWORD@HOST:PORT/DBNAME
GEMINI_API_KEY=your_gemini_key
ADMIN_USERNAME=admin          # optional, defaults to "admin"
ADMIN_PASSWORD=change_me      # required
SESSION_SECRET=change_me      # required
FRONTEND_ORIGINS=http://localhost:5173,http://127.0.0.1:5173  # optional CSV
```

Additional notes:
- `COOKIE_SECURE` (default `true`) can be set to `false` if you need insecure cookies in development.
- Gmail OAuth tokens (generated by the Gmail onboarding flow) should live in `backend/token.json` and remain untracked.
- To use SQLite instead of Postgres, set `DATABASE_URL=sqlite:///./support.db`; SQLAlchemy will create the file automatically.

## Backend setup
```bash
cd backend
python -m venv ../.venv
source ../.venv/bin/activate
pip install -r ../requirements.txt
uvicorn backend.main:app --reload --host 127.0.0.1 --port 8002
```
Key services:
- Session middleware enforces auth on all routes except `/`, `/login`, `/session`, `/static/**`.
- `backend/services/ai.py` loads Gemini 2.5 Flash via `google-genai` and caches the client for reuse.
- `backend/services/gmail.py` handles Gmail sync/send if credentials are provided.

## Frontend setup
```bash
cd support-frontend
npm install
npm run dev        # http://localhost:5173
```
The SPA automatically proxies API calls to `http://localhost:8002` during `npm run dev`. For production builds served by FastAPI:
```bash
npm run build      # outputs to backend/static/
```
Restart the FastAPI server after rebuilding so it serves the latest assets under `/static/`.

## Running the full stack
1. Start the backend with `uvicorn backend.main:app --reload --host 127.0.0.1 --port 8002`.
2. In another terminal, run `npm run dev` inside `support-frontend/`.
3. Open `http://localhost:5173`, sign in with the admin credentials, and manage tickets.

## Workflow overview
1. **Sync** – `/sync-emails` uses `backend/services/gmail.py` to read unread Gmail threads, normalize them into `Ticket` rows, and queue them with status `pending`.
2. **Draft** – Each new ticket immediately calls `generate_reply()` in `backend/services/ai.py`, which contacts Gemini 2.5 Flash and stores the draft in `ai_reply`.
3. **Triage** – The React dashboard calls `/tickets` to display two buckets (Inbox and Sent). Agents filter, edit replies, and save interim work via `/update-reply/{id}` (status flips to `edited`).
4. **Send** – Hitting “Send Reply” triggers `/send-reply/{id}` which validates the draft, dispatches the email through Gmail, and marks the ticket `resolved` so it moves to the Sent column.
5. **Audit** – All actions are logged (auth checks, AI fallbacks, Gmail results) so operators can trace each response in server logs.

## API reference (authenticated)
| Method | Path | Description |
| --- | --- | --- |
| `POST` | `/login` | Create an admin session cookie. |
| `POST` | `/logout` | Clear the session cookie. |
| `GET` | `/session` | Return current session status. |
| `GET` | `/tickets` | List pending vs resolved tickets. |
| `POST` | `/tickets` | Create a ticket with an AI-generated draft reply. |
| `POST` | `/sync-emails` | Pull unread Gmail threads into tickets. |
| `PUT` | `/update-reply/{ticket_id}` | Save manual edits to the draft reply. |
| `POST` | `/send-reply/{ticket_id}` | Send the reply via Gmail (requires draft content). |

All responses are JSON. Session cookies are HTTP-only and respect `SameSite`/`Secure` flags derived from the request host.

## Deployment notes
- Build the frontend (`npm run build`) before deploying the backend so the SPA is available under `/static/`.
- Set `FRONTEND_ORIGINS` to the domains allowed to hit the API (e.g., your Vercel or Render URL).
- Provision the `GEMINI_API_KEY` and Gmail credentials as environment variables/secrets on your hosting provider.
- Rotate `SESSION_SECRET` when rolling credentials, as it invalidates existing sessions.
